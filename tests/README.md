# tests

Регрессионная сеть для `index.html`. Не деплоится: шаг «Prepare site» в
`.github/workflows/deploy-pages.yml` копирует файлы по белому списку, поэтому
эта папка на GitHub Pages не попадает.

## Установка

Нужен headless Chromium от Playwright. Браузер обычно уже есть в
`~/Library/Caches/ms-playwright`; сам пакет ставится без скачивания браузера:

```sh
cd tests
npm init -y
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm i playwright-core
```

Путь к бинарнику задан константой `EXE` в каждом скрипте — поправьте её, если
у вас другая версия Chromium.

## Что чем проверяется

| Скрипт | Что делает |
|---|---|
| `harness.js` | **Главный снапшот.** Прогоняет корпус (~70 строк со всеми фичами движка) и сериализует `analyze()`, `formatAll()`, `fmt()`, `innerHTML` всех слоёв плюс пять операций редактирования (правка ранней строки, вставка в середину, удаление строки, выключение прожектора, возврат). Вывод должен быть **побайтово идентичен** `golden.json`. |
| `tagtest.js` | Тэги и прожекторы. Отдельный скрипт, потому что в чистом профиле `store.tags` пуст — основной снапшот не заходит в код покраски тэгов и в мемо-кэш `wordBoundRe`/`slashTrigRe`. Сверяется с `golden-tags.json`. |
| `caretest.js` | Каретка и выделение. Сверяет `offsetToLineCol()` с наивным `slice/split` **для каждого смещения** в документе, проверяет отрисовку каретки на всех позициях и `.selrange` в номерах строк для всех диапазонов выделения. |
| `seqtest.js` | **Стресс инкрементального рендера.** Прогоняет последовательность (набор, undo×3, redo×2, вставка/удаление строки в середине, полная замена документа, рост до 60 строк, схлопывание до одной, тогл чекбокса) и дампит HTML слоёв после каждого шага. Запускается на текущей и на заведомо хорошей сборке, результаты сравниваются — так проверяется, что диффинг даёт ровно то же, что полная пересборка. |
| `synctest.js` | Движок слияния облачных данных: свежая локальная правка побеждает старое облако, правка с другого устройства побеждает старую локальную, правки в разных документах выживают обе, чистое устройство (`updated:0`) не затирает реальные данные, слияние коммутативно, логические часы переживают перекос часов между устройствами. Проходит одинаково на старых и новых сборках — синхронизацию правки производительности не затрагивали. |
| `bench.js` | Латентность набора: медиана и p90 на 100/300/800 строк, для двух сценариев — дописывание строки в конец и правка строки в середине. |
| `cpuprof.js` | V8 CPU-профиль пути набора: self-time по функциям. Чем пользоваться, когда `bench.js` показал регресс. |
| `moveprof.js` | То же для пути наведения мыши (отдельный путь 60 Гц, не связанный с набором). |
| `startup.js` | Время до редактируемого состояния в четырёх сценариях (вернувшийся пользователь на медленной сети / офлайн, чистый профиль, ссылка `#doc=`), с искусственной задержкой gstatic в 3 с. |
| `swtest.js` | Service worker: регистрация, прекэш, запуск при «лай-фае» (сервер принимает соединение и не отвечает) и полностью офлайн. Поднимает локальный HTTP-сервер, так как SW не регистрируется на `file://`. |
| `fxtest.js` | Политика запросов курсов: документ без валютных команд не должен ходить в сеть вообще. |

## Как гонять

```sh
node harness.js  ../index.html > /tmp/now.json   # затем diff с golden.json
node tagtest.js  ../index.html > /tmp/tags.json  # затем diff с golden-tags.json
node caretest.js ../index.html                   # сам печатает PASS/FAIL
node seqtest.js  ../index.html > /tmp/new.json   # и то же на старой сборке, затем diff
node bench.js    ../index.html "после правки"
node startup.js  ../index.html
node swtest.js   ..                              # каталог, а не файл
node fxtest.js   ../index.html
node synctest.js ../index.html                   # сам печатает PASS/FAIL
```

`harness.js`, `tagtest.js`, `caretest.js` и `seqtest.js` — обязательные: любая правка
рендера, движка или каретки должна оставлять их вывод неизменным. Если вывод
изменился намеренно, пересоздайте golden-файлы и опишите в коммите, что именно
изменилось и почему.

## Известное несовпадение (не баг)

`startup.js` печатает `TypeError: Compressed input was truncated` для сценария
`#doc=`: тест подставляет заведомо мусорный хэш. То же самое происходит на
исходной версии — это ожидаемо.
