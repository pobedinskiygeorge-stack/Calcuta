# tests

Регрессионная сеть для `index.html`. Не деплоится: шаг «Prepare site» в
`.github/workflows/deploy-pages.yml` копирует файлы по белому списку, поэтому
эта папка на GitHub Pages не попадает.

## Установка

Нужен headless Chromium от Playwright. Браузер обычно уже есть в
`~/Library/Caches/ms-playwright`; сам пакет ставится без скачивания браузера:

```sh
cd tests
npm init -y
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm i playwright-core
```

Путь к бинарнику задан константой `EXE` в каждом скрипте (в новых — можно переопределить переменной окружения `CALCUTA_CHROME`) — поправьте её, если
у вас другая версия Chromium.

## Что чем проверяется

| Скрипт | Что делает |
|---|---|
| `harness.js` | **Главный снапшот.** Прогоняет корпус (~70 строк со всеми фичами движка) и сериализует `analyze()`, `formatAll()`, `fmt()`, `innerHTML` всех слоёв плюс пять операций редактирования (правка ранней строки, вставка в середину, удаление строки, выключение прожектора, возврат). Вывод должен быть **побайтово идентичен** `golden.json`. |
| `tagtest.js` | Тэги и прожекторы. Отдельный скрипт, потому что в чистом профиле `store.tags` пуст — основной снапшот не заходит в код покраски тэгов и в мемо-кэш `wordBoundRe`/`slashTrigRe`. Сверяется с `golden-tags.json`. |
| `caretest.js` | Каретка и выделение. Сверяет `offsetToLineCol()` с наивным `slice/split` **для каждого смещения** в документе, проверяет отрисовку каретки на всех позициях и оверлей многострочного выделения. |
| `seqtest.js` | **Стресс инкрементального рендера.** Прогоняет последовательность (набор, undo×3, redo×2, вставка/удаление строки в середине, полная замена документа, рост до 60 строк, схлопывание до одной, тогл чекбокса) и дампит HTML слоёв после каждого шага. Запускается на текущей и на заведомо хорошей сборке, результаты сравниваются — так проверяется, что диффинг даёт ровно то же, что полная пересборка. |
| `synctest.js` | Движок слияния облачных данных: свежая локальная правка побеждает старое облако, правка с другого устройства побеждает старую локальную, правки в разных документах выживают обе, чистое устройство (`updated:0`) не затирает реальные данные, слияние коммутативно, логические часы переживают перекос часов между устройствами. Проходит одинаково на старых и новых сборках — синхронизацию правки производительности не затрагивали. |
| `staletest.js` | **Отставшее устройство не затирает облако.** Гоняет настоящие пути записи (`pushCloudNow`/`flushSync`/`keepaliveFlush`/`hardSave`/`refreshFromServer`) через шов `__calcuta.__syncTest` против фейкового Firestore: сворачивание/закрытие «спящей» вкладки не пишет в облако; правка с отставшего устройства **сливается** с серверной версией (обе на месте, новые документы с другого устройства выживают); при пробуждении вкладка сразу подтягивает серверную копию; keepalive при закрытии пишет только `pending.<ключ>` (несинхронизированные документы + их базы), даже после долгого сна, а следующий читатель вливает его и очищает; «Сохранить на всех устройствах» на отставшем устройстве мерджится, а не откатывает; офлайн-пуш падает без записи и доезжает слиянием; чужой более новый hard save принимается, а правка, сделанная после него, сохраняется. |
| `devicetest.js` | **Несколько устройств.** 43 сценария на симуляторе `devicesim.js`: каждое «устройство» — отдельный профиль Chromium с настоящим `index.html`, фейковый Firebase SDK ходит в общий «сервер» в Node (оптимистичные транзакции, слушатели, REST PATCH с маской полей). Устройства спят, выходят из сети, выключаются без событий выгрузки, закрываются, получают перекос часов на сутки, зависший канал, убитый слушатель, опоздавший старый снимок, недогрузившийся при включении Firebase, сон с закрытой крышкой без событий, «тихо умерший» слушатель; простаивают через «пульс» перечитывания; новое устройство, которым пользовались до входа; печатают одновременно с клавиатуры, в том числе во время слияния и IME-композиции; две вкладки на одном устройстве; удаление против правки; переименование против правки; hard save; присланная ссылка `#doc=`. Инварианты: ни одна правка не теряется, отметка времени документа на сервере никогда не уменьшается при изменении его текста (на этом держится распознавание опоздавших снимков), старая копия никогда не перезаписывает более новую, все устройства сходятся к серверной версии, простаивающие устройства не пишут в облако. Последний сценарий — фаззинг: 3 устройства, 70 случайных шагов (`FUZZ_SEED=<n>` задаёт сид). `node devicetest.js ../index.html [регэксп-фильтр]`. |
| `mergetest.js` | **Движок трёхстороннего слияния** (`merge3`, `mapOffset`, `mergeStores`): фиксированные случаи (разные строки, соседние строки, одна строка в разных местах, вставки в одну точку, удаление строки рядом с правками, настоящие конфликты) и рандомизированные свойства на десятках тысяч пар параллельных правок: ничего добавленного не теряется; далёкие правки сливаются ровно; нетронутые строки остаются ровно один раз; параллельные вставки (в том числе внутрь слов) не дублируют строк; каретка остаётся на том же тексте. |
| `realsdk.js` | **Настоящий Firebase.** Ключевые сценарии и фаззинг (`FUZZ_SEED=<n>`) на **настоящем** Firestore SDK (compat 10.12.2 из npm-пакета `firebase`) против **настоящего** эмулятора Firestore — проверяет допущения фейкового SDK из `devicesim.js`: живое обновление, трёхстороннее слияние через настоящую транзакцию, выключенное устройство, одновременные транзакции с двух устройств, загрузка без связи с сервером, разрыв сети без событий, подвисший канал Listen, отказ правил посреди сессии (слушатель умирает с ошибкой), hard save, close-flush через REST PATCH с вложенной маской `pending.<ключ>`, рекомендуемые правила `firestore.rules` (новая сборка пишет, сборка без `proto` — нет; со старой сборкой задайте `OLD_BUILD=<путь к index.html>`). Подменён только вход Google. На предыдущей сборке три сценария теряют правки, а фаззинг — 17 правок из ~27. Подготовка: `java -jar cloud-firestore-emulator-v1.19.7.jar --host=127.0.0.1 --port=8085` (JAR — `storage.googleapis.com/firebase-preview-drop/emulator/`), `npm pack firebase@10.12.2 && tar xzf firebase-10.12.2.tgz`; запуск: `FB_DIR=<…/package> EMU=127.0.0.1:8085 node realsdk.js ../index.html`. |
| `updatetest.js` | **Обновление приложения.** Поднимает HTTP-сервер, «деплоит» новую сборку и проверяет, что открытая страница подхватывает новый service worker, не перезагружается на глазах у пользователя, перезагружается на новую сборку, когда вкладка скрыта, без петли перезагрузок, а свежий запуск после деплоя сразу получает новую страницу (не из HTTP-кэша). `node updatetest.js ..` (каталог). |
| `featuretest.js` | **Взаимодействие всех функций** (82 сценария реальными нажатиями): задачи `/текст` и `/(текст)` против переменных, тэгов, дат, валюты и вставки; `#`, `//`, чекбоксы; автозакрытие пар против маркера округления, Enter и выделения; Backspace/Delete/Ctrl/Alt/Cmd-удаление; undo/redo, в том числе вставки; Ctrl+F через разряды; тап — единственный способ отметить задачу; миграции сохранённых документов. Сам печатает PASS/FAIL. |
| `edittest.js` | **Правка поверх вставных символов** (группировка разрядов, автоотступ, пробел после `//`, старая отбивка U+00A0): Backspace/Delete/Ctrl+Backspace не застревают на них и не тащат их за собой — и с клавиатуры, и как с экранной клавиатуры телефона (только `beforeinput`). Сам печатает PASS/FAIL. |
| `bench.js` | Латентность набора: медиана и p90 на 100/300/800 строк, для двух сценариев — дописывание строки в конец и правка строки в середине. |
| `cpuprof.js` | V8 CPU-профиль пути набора: self-time по функциям. Чем пользоваться, когда `bench.js` показал регресс. |
| `moveprof.js` | То же для пути наведения мыши (отдельный путь 60 Гц, не связанный с набором). |
| `startup.js` | Время до редактируемого состояния в четырёх сценариях (вернувшийся пользователь на медленной сети / офлайн, чистый профиль, ссылка `#doc=`), с искусственной задержкой gstatic в 3 с. |
| `swtest.js` | Service worker: регистрация, прекэш, запуск при «лай-фае» (сервер принимает соединение и не отвечает) и полностью офлайн. Поднимает локальный HTTP-сервер, так как SW не регистрируется на `file://`. |
| `fxtest.js` | Политика запросов курсов: документ без валютных команд не должен ходить в сеть вообще. |

## Как гонять

```sh
node harness.js  ../index.html > /tmp/now.json   # затем diff с golden.json
node tagtest.js  ../index.html > /tmp/tags.json  # затем diff с golden-tags.json
node caretest.js ../index.html                   # сам печатает PASS/FAIL
node seqtest.js  ../index.html > /tmp/new.json   # и то же на старой сборке, затем diff
node bench.js    ../index.html "после правки"
node startup.js  ../index.html
node swtest.js   ..                              # каталог, а не файл
node fxtest.js   ../index.html
node synctest.js ../index.html                   # сам печатает PASS/FAIL
node staletest.js ../index.html                  # сам печатает OK/FAIL
node mergetest.js ../index.html                  # сам печатает ok/FAIL
node devicetest.js ../index.html                 # ~10 мин; второй аргумент — фильтр-регэксп
node updatetest.js ..                            # каталог, а не файл
FB_DIR=… EMU=127.0.0.1:8085 node realsdk.js ../index.html   # нужен эмулятор Firestore, см. таблицу
node edittest.js  ../index.html                   # сам печатает PASS/FAIL
node featuretest.js ../index.html                 # сам печатает PASS/FAIL
```

`harness.js`, `tagtest.js`, `caretest.js` и `seqtest.js` — обязательные: любая правка
рендера, движка или каретки должна оставлять их вывод неизменным. Если вывод
изменился намеренно, пересоздайте golden-файлы и опишите в коммите, что именно
изменилось и почему.

## Известное несовпадение (не баг)

`startup.js` печатает `TypeError: Compressed input was truncated` для сценария
`#doc=`: тест подставляет заведомо мусорный хэш. То же самое происходит на
исходной версии — это ожидаемо.
