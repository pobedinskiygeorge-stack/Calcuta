# Calcuta

Текстовый редактор с живой математикой в стилистике редактора кода — вдохновлён [numbr.dev](https://numbr.dev), с рядом доработок. Тёмная и светлая темы, минималистичный интерфейс.

Всё приложение — один самодостаточный файл `index.html` (HTML + CSS + JS, без сборки и зависимостей). Просто открой его в браузере.

## Возможности

| Что | Как |
|---|---|
| **Живой расчёт** | Любое выражение считается на лету, результат — в правой колонке в овальной «пилюле». Клик по пилюле копирует чистое число; при наведении подсвечивается исходная строка. |
| **Математика** | `+ - * / ^ %`, скобки, суффиксы `k`/`M`, проценты (`100 + 25%`, `25% of 100`). Слова-контекст вокруг чисел игнорируются. |
| **Цвета операций** | Числа, участвующие в расчёте, — **небесно-голубые**; рабочие знаки (`+ − × ÷ ^ %`) — **оранжевые** (тот же half-life-оранжевый, что у курсора и всего интерфейса) и автоматически отделяются пробелами (`2+2` → `2 + 2`); `=` приглушён. |
| **Скобки** | Пара скобок подсвечивается, только если она реально участвует в расчёте — по глубине вложенности, базовыми цветами приложения (снаружи внутрь: **зелёный** → **оранжевый** → **фиолетовый**, дальше цикл повторяется до любой глубины). Скобки, просто обрамляющие слова (`заметка (важно) 100 + 50`), остаются обычным цветом текста. Клик/курсор рядом с одной скобкой подсвечивает её пару. |
| **Переменные** | `бюджет = 500k` — подсветка **зелёным**, максимальный приоритет. Используются дальше по тексту. Область действия — **свой раздел `//`**: переменная видна и используется только между своим заголовком `//` и следующим; в другом разделе то же имя можно задать заново с независимым значением, без конфликта. Успешно заданная переменная (везде, где упоминается) ведёт себя как пилюля: клик копирует её **имя** (значение и так видно в столбце результатов), двойной клик ставит курсор внутрь для обычного редактирования написания, а Backspace вплотную после неё стирает имя целиком за одно нажатие. При наведении курсора появляется овальный фон-подсветка (только пока курсор над ней); в остальное время — обычный зелёный текст без окантовки. |
| **Округление** | `()` (пустые скобки) в любом месте строки округляет её результат **вверх до десятков** — `1343 ()` → `1350`, `500 / 3 ()` → `170`. Можно ставить и между именем переменной и `=` (`итого () = 1000 * 1.25`). Сами скобки автоматически отбиваются пробелами, как знаки операций. |
| **Результат-пилюля** | Клик по результату копирует **чистое число** (без невидимых символов и группировки), которое читается как число в Google Таблицах / Excel / Word. Числа, вставленные из этих сервисов (в т.ч. с неразрывными пробелами-разделителями), распознаются и участвуют в расчётах. |
| **Ссылки** | Ссылка (`https://…`, `http://…`, `www.…`) отображается кликабельной пилюлей; клик открывает её в новой вкладке без подтверждения. Ведёт себя как пилюля: курсор внутрь не заходит, Backspace удаляет её целиком. Форматирование чисел/операторов и матпарсер ссылку не трогают. |
| **Агрегация** | `sum`/`сумм` складывает **непрерывный блок** результатов прямо над строкой (пустая строка обрывает блок), `avg`/`среднее` — среднее, `prev`/`пред` — предыдущий результат. |
| **Чекбоксы** | Команды `++` или `хх` в начале строки (либо `++`/отдельное `хх` в конце) сразу превращают её в чекбокс (удобно на телефоне). Скобки маркера — оранжевые, отмеченный `[x]` целиком зелёный. Клик по галочке → зелёный фон, бледный текст. Удалить строку можно обычным стиранием, правым кликом (меню на десктопе) или долгим нажатием на телефоне. |
| **Поиск в документе** | `Ctrl/Cmd+F` — find-бар над редактором: подсветка совпадений, счётчик, навигация `↑`/`↓` (или `Enter`/`Shift+Enter`). |
| **Undo/Redo** | `Ctrl/Cmd+Z` — отмена, `Ctrl/Cmd+Shift+Z` (или `Ctrl+Y`) — повтор. Свой стек истории (нативный ломается из-за живого форматирования). |
| **Backspace** | Обычное поведение: стирает **один знак**; `Ctrl/Alt+Backspace` — целое слово. |
| **Ширина результатов** | На десктопе правую колонку можно тянуть за разделитель, ширина сохраняется. Текст всегда переносится по словам, а не прячется под колонкой. На телефоне ширина фиксирована (разделитель убран). |
| **Телефон** | Чуть крупнее масштаб для читаемости (жертвуя числом видимых строк); шрифт ≥16px, поэтому фокус на редакторе не вызывает авто-зум iOS. Номера строк прижаты к левому краю узким столбцом. |
| **Надзадачи и иерархия** | Строка с `//` — надзадача: фиолетовый текст на фиолетовой заливке во всю строку (две надзадачи подряд сливаются в один блок). Всё под ней получает визуальный отступ; курсор «не чувствует» отступ — строка ведёт себя как обычная. Подзадачи белые. |
| **Тэги** | Задаются в раскрывашке по клику на **calcuta** в топбаре (текст + цвет), общие для всех документов. Квадратик рядом с полем открывает палитру — те же базовые цвета, что и у номеров строк (произвольный цвет задать нельзя, чтобы палитра приложения оставалась замкнутой); добавление — по **Enter** (кнопки «+» нет). Цвет уже добавленного тэга меняется тапом/кликом по его кружочку — открывается та же палитра. Подсветка тэга приоритетнее всего, кроме переменных. Команда `/тэг`, набранная где угодно в документе, включает «прожектор»: пока она есть в тексте, все строки с этим тэгом подсвечиваются его цветом целиком (сам текст команды остаётся видимым); уберите `/тэг` — подсветка гаснет. Там же — краткий справочник по синтаксису и функциям. |
| **Даты** | Формат `дд.мм` (двузначный месяц) подсвечивается жёлтым. Команда `/дд.мм`, набранная где угодно в документе, включает «прожектор» для этой даты по аналогии с тэгами: пока она есть в тексте, все строки с этой датой подсвечиваются целиком (жёлтым фоном), кроме самой строки с командой — она подсвечивается, только если дата встречается на ней ещё раз отдельно. Уберите `/дд.мм` — подсветка гаснет. |
| **Числа** | Группировка тысяч (визуальная, тонкий пробел), десятичный разделитель — **запятая**: точка автоматически превращается в запятую (`3.14 → 3,14`, `1234.56 → 1 234,56`). При копировании пробелы убираются; при вставке любой формат (`1,234.56`, `1 234,56`, `рррр.кк`) приводится к `р ррр,кк`. |
| **Номера строк** | Узкий лаконичный столбец слева. Выделяй номера (клик, Shift, Ctrl или **перетаскиванием**) и задавай им цвет через правый клик — из палитры базовых цветов приложения. |
| **Наведение** | Подсветка всей строки — только как «отсылка»: при наведении на пилюлю-результат подсвечивается её строка, при наведении на переменную — строка, где она задана. Просто строка под курсором не подсвечивается. Выделение текста — бледно-бирюзовое и полупрозрачное (как в Claude Code): подсветка синтаксиса читается сквозь него, цвет символов не подменяется. Этот оттенок больше нигде в интерфейсе не встречается. |
| **Документы** | Всё управление — в топбаре (боковое меню упразднено). Стоковые страницы **«Задачи»** и **«Личное»** — отдельные кнопки с белыми названиями; открытая помечается серым фоном. Все документы и все действия с ними — под **лупой**: строка поиска (по имени и содержимому, у совпавших по тексту — счётчик), первой строкой тонкий `+ новый документ`, ниже полный список. Клик — открыть, двойной клик по имени — переименовать, `×` — удалить (с подтверждением). Стоковые страницы не переименовываются и не удаляются. |
| **Тема** | Тёмная (по умолчанию) и светлая. Переключатель — в раскрывашке по клику на **calcuta** в топбаре. Выбор хранится локально на устройстве (`localStorage`, не синхронизируется) и применяется до первой отрисовки, без мелькания. |
| **Автосохранение** | Документы (текст, название, цвета строк) и тэги хранятся в `localStorage`. |

## Палитра

Приложение ограничено пятью базовыми цветами. В CSS они объявлены один раз (`:root` — тёмная тема, `:root.light` — светлая), а все остальные цветовые токены — только псевдонимы `var(...)`, поэтому шестому оттенку взяться неоткуда. Выбор цвета пользователем (номера строк, тэги) ограничен этим же набором.

| Цвет | Тёмная / светлая | Где |
|---|---|---|
| Оранжевый (half-life) | `#e8802c` / `#c16315` | акцент интерфейса, курсор, знаки операций, `текст:`-лейблы, скобки чекбокса, скобки 2-го уровня |
| Зелёный | `#5ecb7e` / `#2da44e` | переменные, результаты, галочка `[x]`, внешние скобки |
| Фиолетовый | `#b98cf5` / `#7c4dd6` | надзадачи `//`, цитаты, скобки 3-го уровня |
| Голубой | `#7ec8f5` / `#2b7fc4` | числа, ссылки |
| Жёлтый | `#e3b755` / `#b07d10` | даты, валютные команды, поиск |

Цвета, выбранные до замыкания палитры (когда цвет тега задавался свободным пикером), подтягиваются к ближайшему базовому при загрузке и при каждом снапшоте из облака. Близость считается по CIEDE2000, а не по простому расстоянию в Lab: например вермильон `#d13a20` по ΔE76 стоит в 30.2 от оранжевого и в 31.3 от красного — подбрасывание монетки, которое выпадает на оранжевый, — тогда как ΔE2000 уверенно относит его к красному (17.5 против 20.9).

Сверх базы — только нейтрали (фон, границы, текст, комментарии), красный `#f14065` для удаления и ошибок (единственный, одинаковый в обеих темах), и бирюза выделения `rgba(122,214,209,.24)`, которая не используется больше нигде.

## Приоритет подсветки

`Переменная (зелёный) → Тэг → Надзадача // (фиолетовый) → Дата (жёлтый) → Число (голубой)`

## Синтаксис — коротко

```
// Бюджет проекта
доход = 2 500 000
налог = доход * 13%
чистыми = доход - налог
[ ] согласовать смету
[x] отправить отчёт 15.09
sum
```

## Заметки о формате чисел

- Десятичный разделитель — **запятая** (`12,5`). Точка в `дд.мм` трактуется как **дата** — это снимает конфликт «дата vs дробь».
- Число, введённое подряд (`2500000`), автоматически группируется тонким пробосом (`2 500 000`). Пробелы визуальные — копирование даёт `2500000`.

## Разработка / тесты

Логика движка вынесена в `window.__calcuta` (`analyze`, `evaluate`, `fmt`, `regroupText`, …), что позволяет юнит-тестировать её из headless-браузера без UI.

## Деплой на GitHub Pages

Workflow `.github/workflows/deploy-pages.yml` уже в репозитории и публикует `index.html` при каждом пуше в `claude/math-text-editor-4gmzl2`. Нужно один раз включить сам Pages (это делает только владелец репозитория через UI, API-доступа для этого нет):

1. Repo → **Settings → Pages**.
2. **Build and deployment → Source** → выбрать **GitHub Actions**.
3. Сделать любой пуш (или запустить workflow вручную во вкладке Actions) — сайт появится по адресу вида `https://<username>.github.io/<repo>/`.

## Вход через Google и синхронизация между устройствами

Экран входа и синхронизация документов реализованы через Firebase (Authentication + Firestore) — секция `[SYNC]` в `index.html`, сразу перед `[BOOT]`. Пока `firebaseConfig` не заполнен настоящими значениями, приложение показывает окно входа с сообщением «Firebase ещё не настроен» и кнопка входа неактивна — сама заметка/редактор при этом недоступны, ровно как задумано.

Чтобы включить:

1. **console.firebase.google.com** → создать проект (бесплатного тарифа Spark достаточно).
2. **Authentication → Sign-in method** → включить провайдера **Google**.
3. **Firestore Database** → создать базу (любой регион, «production mode»), затем во вкладке **Rules** вставить:
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /users/{uid} {
         allow read, write: if request.auth != null && request.auth.uid == uid;
       }
     }
   }
   ```
4. **Project settings → General → Your apps** → добавить веб-приложение, скопировать объект `firebaseConfig`.
5. Вставить эти значения в `firebaseConfig` в `index.html` (секция `[SYNC]`), заменив плейсхолдеры `ЗАМЕНИТЕ_НА_СВОЙ…`. Значения не секретные — их можно спокойно коммитить.
6. **Authentication → Settings → Authorized domains** → добавить домен, на котором развёрнут сайт (например `<username>.github.io`), иначе вход через Google будет отклонён.

После этого документы хранятся в Firestore под `users/{uid}` (весь `store` — одним JSON-полем) и синхронизируются между устройствами.

Синхронизация **помердживается по каждому документу** (а не «победил последний, кто сохранил весь `store`»): при каждом снимке `onSnapshot` локальная и облачная версии сливаются по полю `updated` у каждого документа, с «надгробиями» (`deletedDocs`) для удалённых — так правки разных документов на разных устройствах не затирают друг друга, перекос часов между устройствами не приводит к потере данных, а свежесозданные стоковые страницы (у них `updated:0`) никогда не могут перезаписать реальные данные из облака. **Тэги сливаются точно так же — по каждому тэгу** (ключ — имя тэга в нижнем регистре, у каждого своё `updated`, удаления фиксируются надгробиями `deletedTags`): раньше весь список тэгов синхронизировался по принципу «победил последний», из-за чего тэг, добавленный на одном устройстве, мог тихо пропасть (и это ломалось при перекосе часов); теперь добавления с разных устройств объединяются, а удаление тэга корректно доходит до всех. Слияние детерминированное и коммутативное, поэтому все устройства сходятся к одному состоянию. Правки уходят в облако с небольшой задержкой и прилетают на другие вкладки/устройства вживую; текст документа, в котором вы прямо сейчас печатаете, при этом не выдёргивается из-под курсора, а `activeId`/ширина колонки результатов остаются локальными для устройства. Первая загрузка не отправляет ничего в облако, пока не сверится с ним (флаг `cloudReady`) — чтобы пустое/только что открытое устройство не затёрло облачную копию. **Первая сверка идёт только по данным с сервера, а не из кэша:** подписка открывается с `{includeMetadataChanges:true}`, и снимки с `metadata.fromCache` игнорируются до первой серверной сверки. Иначе телефон, стартующий офлайн или с холодным кэшем, получал бы снимок, где облачный документ «пустой», срабатывала ветка «облако пусто → засеять», и устройство перезаписывало реальные данные своими стоковыми страницами — записи пропадали. Теперь пока сервер не ответит, устройство не считает облако пустым и ничего в него не пишет.
